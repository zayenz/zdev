The brief describes what to build and why. Tasks break that objective into
work that can be implemented and checked. Decisions, dependencies, and results
stay with the repository, so another agent or a later session can continue
without reconstructing the plan from chat history.

The CLI manages this record. The installed skill gives your coding agent
workflows for exploring an objective, creating tasks, and carrying out the
approved work. You can ask for one task, a loop through an area, or compatible
tasks in parallel.

You can run the terminal commands in these docs yourself or ask your agent to
run them and explain the result. The agent uses the same CLI to manage records;
its workflows also coordinate the development work.

## Start with one change

An *area* groups work toward an objective. Its brief records what you agreed
to build and the boundaries of the change. Individual Markdown tasks describe
the work and how to check it, under `.zdev/` in your repository.

In your coding-agent chat, you might start with:

```text
Use zdev to explore adding --name NAME to hello.py.
Keep the current greeting when no name is supplied.
```

The agent helps turn the objective into a brief and a proposed task bundle.
Once you approve the work, it can implement the tasks, run the agreed checks,
and have a separate agent review the implementation and verify each result
before committing it. The record shows what is finished and what remains.

The [first-task tutorial](./guides/getting-started/) takes that example through
installation, planning, approval, and a completed task.

## Where it runs

The binary supports macOS and Linux on x86-64 and Arm64. Codex, Claude Code,
OpenCode, Pi, Oh My Pi, and Google Antigravity have integrations. Delegation,
parallel work, and continuation support vary by harness; check the
[harness reference](./guides/user-guide/#harness-notes) before choosing a
long-running workflow. Zdev does not provide its own model service.
